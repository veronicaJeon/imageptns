# 중복 이미지 탐지·차단 기준

> 상태: 1단계 구현·관찰 중
> 작성일: 2026-08-06
> 구현일: 2026-08-06

## 결론

현재 규모와 Vercel·Supabase 구조에서는 외부 AI나 LLM보다 원본 `SHA-256`과 시각 지문 `pHash + dHash`를 결합하는 방식이 가장 적합하다.

- 같은 사진가의 SHA-256 일치: 확정 중복으로 업로드 차단
- 다른 사진가의 SHA-256 일치: 자동 삭제하지 않고 관리자 `중복` 검토 대상으로 분류, 일반 승인·공개 차단
- pHash·dHash 근접: 초기에는 자동차단하지 않고 관리자 검토 후보로 수집
- 2~4주 관찰에서 충분한 정밀도가 확인된 뒤 같은 사진가의 초고신뢰 유사 중복만 제한적으로 차단
- CLIP·LLM·외부 비전 API는 의미가 비슷한 정상 사진까지 중복으로 판단할 위험과 비용이 있어 1차 방식으로 사용하지 않음

“자동차단”은 같은 사진가의 확정 중복에 대해서는 업로드 거부를 뜻하고, 다른 사진가와의 일치에 대해서는 삭제가 아니라 공개·판매 승인의 자동 보류를 뜻한다.

## 탐지 지점

서버의 업로드 API가 비공개 Storage 원본을 내려받은 직후, 워터마크·미리보기를 생성하기 전에 계산한다. 이 시점에는 원본 Buffer가 이미 존재하므로 SHA-256을 위한 추가 다운로드가 없다.

브라우저가 presign 전에 SHA-256을 계산해 빠른 사전 경고를 줄 수는 있지만 신뢰 경계가 아니므로 서버 계산과 DB 판정을 대체하지 않는다.

현재 온체인 `content_hash`는 이미지 바이트 해시가 아니라 여러 증명 데이터를 결합한 값이므로 중복 탐지에 재사용하지 않는다. `proof_original_sha256`는 일부 온체인 이미지에만 존재하므로 기존 데이터 백필의 보조값으로만 사용한다.

## 판정 기준

| 신호 | 같은 사진가 | 다른 사진가 |
| --- | --- | --- |
| 원본 SHA-256 일치 | `409 DUPLICATE_UPLOAD`, 업로드 세션의 임시 원본 정리 | `duplicate_review=required`, 공개·승인 차단 |
| pHash와 dHash 모두 초고신뢰 | 관찰 후 제한적 자동차단 가능 | 관리자 검토만 허용 |
| 한 지문만 근접 또는 일반 유사 | 경고·검토 참고 | 검토 참고 |
| 의미만 비슷한 장면 | 허용 | 허용 |

pHash 단독 차단은 금지한다. 단색·저정보 이미지 충돌을 줄이기 위해 dHash, 종횡비, 크기와 함께 판단한다. 크롭·반전·테두리·텍스트 합성 우회가 실제로 유의미해질 때만 crop-resistant hash나 별도 임베딩 서비스를 검토한다.

## 데이터 설계

### `image_fingerprints`

- `image_id`, `photographer_id`
- `original_sha256`
- 64비트 `phash`, `dhash`
- `width`, `height`, `algorithm_version`, `created_at`

### 업로드·이미지 상태

- `image_fingerprints`: 업로드 세션별 원본 SHA-256, pHash, dHash, 크기, 알고리즘 버전과 삭제 지문 tombstone
- `images`: `duplicate_review_status`(`clear`, `required`, `confirmed`, `overridden`), 후보 지문, match 종류·거리, 검토자·검토시각·사유

DB 제약으로 `is_published=true`인 이미지는 `duplicate_review_status`가 `clear` 또는 `overridden`이어야 한다. 관리 API가 실수해도 검토 대상이 공개되지 않아야 한다.

동시 업로드 경합은 SHA-256과 사진가를 기준으로 DB advisory lock을 잡고 지문을 예약하는 원자 함수로 막는다. 단순 조회 후 insert만 사용하면 두 요청이 함께 통과할 수 있다.

## 화면과 운영

사진가 화면은 상대 사진가나 상대 이미지 식별정보를 노출하지 않는다.

- 본인 확정 중복: `[사진 설명]의 사진은 기존 이미지와 중복이므로 업로드에 실패했습니다.`
- 유사 후보와 다른 권리자 일치: 업로드는 접수하되 상대 이미지 정보는 노출하지 않는다.
- 다중 업로드: 중복 파일만 실패시키고 나머지는 계속 처리

관리자 검토 화면은 `중복` 배지, 후보 두 장, exact/visual 구분, pHash·dHash 거리를 보여준다. `별도 이미지로 승인`은 사유와 감사로그가 필수이며 DB 제약도 일반 공개를 차단한다.

반려된 동일 원본도 재업로드를 차단한다. 완전삭제된 이미지의 지문은 1년간 tombstone으로 유지한 뒤 매일 정리한다. 업로드 안내의 반복 등록 제한과 이의제기 경로는 공개 전 정책 문구 과제로 유지한다.

## 단계별 구현

1. **완료** — 정확 중복: SHA-256, 원자 판정 함수, 같은 사진가 거부, 다른 사진가 검토 분류
2. **진행 중** — 관찰 모드: 종횡비 차이 1% 이하, pHash 거리 12 이하와 dHash 거리 4 이하 후보를 표시하고 2~4주간 관찰
3. 제한적 자동차단: 같은 사진가, 종횡비 차이 1% 이하, 두 지문 모두 초고신뢰이며 검증 정밀도 99.5% 이상일 때만 활성화
4. 고도화: 실제 우회 사례와 규모가 정당화할 때 crop-resistant hash·band index·별도 임베딩 서비스 검토

기존 이미지 백필은 `scripts/backfill-image-fingerprints.mjs`를 운영 환경 확인 플래그와 함께 실행한다. 각 이미지 결과는 독립 저장되므로 재실행 가능하며, 원본을 읽을 수 없는 항목은 실패 목록으로 남긴다.

## 필수 검증

- 파일명만 바꾼 동일 파일의 SHA 차단
- EXIF 변경, JPEG 재압축·리사이즈의 시각 지문 탐지
- 서로 다른 사진과 단색 이미지 오탐 방지
- EXIF 회전과 사용자 회전 정규화
- 같은 파일 동시 업로드 시 하나만 성공
- 확정 중복 거부 후 이미지·미리보기·원본 잔존 없음
- 다른 사진가 중복에서 상대 정보 비노출
- `duplicate_review=required` 승인·공개 DB 차단
- 관리자 override 사유·감사로그
- 반려·archived·purged 이미지 재업로드 정책
- 100MB·120MP 경계 성능과 서버 실행 제한

## 후속 결정

1. 다른 사진가 exact match의 권리 확인 담당자와 이의제기 SLA
2. 관찰 모드 2~4주 결과와 자동차단 정밀도 기준 승인
3. 기존 이미지 cursor 기반 지문 백필 실행 승인
4. 관리자 `중복 확정` 전용 처리와 이의제기 화면의 필요성
