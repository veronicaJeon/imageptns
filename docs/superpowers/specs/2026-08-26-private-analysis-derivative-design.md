# 비공개 분석 사본 파이프라인 설계

> 상태: 승인된 구현 기준
> 기준일: 2026-08-26

## 문제

현재 의미 인덱싱과 보조 캡션은 공개 `images-preview`의 워터마크 파생본을 입력으로 사용한다. 이 경로는 원본 해상도를 유지해 외부 공급자의 픽셀 제한을 넘을 수 있고, 워터마크가 이미지 주제·분위기 신호에 불필요한 노이즈를 더한다.

## 결정

업로드 원본을 방향 보정한 뒤 긴 변 1,600px 이내 JPEG로 축소하고 메타데이터를 제거한 `analysis-v1` 사본을 만든다. 사본은 공개 정책이 없는 전용 비공개 `images-analysis` 버킷에 저장한다.

```text
비공개 원본
  └─ 방향 보정·축소·메타데이터 제거
       └─ 비공개 analysis-v1 JPEG
            ├─ 승인 후 Voyage 임베딩
            ├─ 권한 확인 후 NVIDIA 보조 캡션
            └─ 워터마크 합성 → 공개 시안·썸네일
```

워터마크 생성과 외부 AI 호출은 분석 사본을 공통 입력으로 사용하지만 서로의 성공 여부에 의존하지 않는다. 업로드·검토 시 공개 시안 생성은 계속 가능하고, 외부 임베딩 호출은 기존 정책대로 승인·공개 이후에만 수행한다.

## 데이터와 버전

- `images.storage_path_analysis`와 `images.analysis_derivative_version`에 현재 비공개 사본을 기록한다.
- 공개 `storage_path_preview`와 구매 원본 경로는 유지한다.
- 의미 임베딩의 내부 `model_version`에는 `analysis-v1` 입력 버전을 덧붙여 기존 워터마크 입력 벡터와 혼합하지 않는다.
- 기존 승인 이미지는 새 버전의 백필 작업이 처음 처리될 때 비공개 원본에서 사본을 생성한다. 원본을 읽을 수 없으면 공급자 호출 전에 안전한 내부 오류로 실패 처리한다.

## 보안·보존

- 분석 사본 버킷에는 공개·authenticated 읽기 정책을 만들지 않는다. 서비스 역할 서버 경로만 접근한다.
- JPEG 변환 시 EXIF, 원래 파일명과 위치 메타데이터를 포함하지 않는다.
- 업로드 실패, 만료 세션, 반려 후 완전삭제와 관리자 완전삭제에서 분석 사본도 함께 제거한다.
- 공개 화면과 API 응답에는 분석 사본 경로를 포함하지 않는다.

## 수용 기준

1. 신규 업로드가 1,600px 이하 무워터마크 JPEG 분석 사본과 그 사본에서 만든 공개 워터마크 시안을 생성한다.
2. 의미 인덱싱과 NVIDIA 캡션은 `images-preview`가 아니라 비공개 분석 사본만 사용한다.
3. 기존 승인 이미지는 새 의미 인덱스 백필 중 분석 사본을 지연 생성한다.
4. 기존 워터마크 기반 벡터는 삭제하지 않고 새 입력 버전과 분리한다.
5. 완전삭제와 실패 정리가 분석 사본을 빠뜨리지 않는다.
6. 마이그레이션, 단위·정책 테스트, 타입, 린트, 전체 테스트와 빌드가 통과한다.
