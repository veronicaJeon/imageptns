# 사진으로 검색 1단계 설계

## 목표

구매자가 가진 참고 사진을 공개 라이브러리에 저장하지 않고 분석해, 동일하거나 리사이즈·재인코딩·가벼운 편집을 거친 사진을 찾을 수 있게 한다. 업로드 중복 탐지와 같은 SHA-256, pHash, dHash 생성기를 재사용해 두 기능의 판정 기반을 하나로 유지한다.

## 1단계 범위와 한계

- 공개 라이브러리 검색 화면에서 JPEG, PNG, WebP 파일 한 장을 선택한다.
- 브라우저는 최대 25MB 원본을 긴 변 1,600px 이하 JPEG 검색본으로 만들며 EXIF와 원래 파일명을 제거한다. 서버에는 3.5MB 이하 검색본만 보낸다.
- 서버 메모리에서 지문을 계산하고 요청이 끝나면 입력 바이트를 보관하지 않는다.
- `approved`, `active`, `is_published=true`인 이미지 중 현재 알고리즘 버전의 지문이 있는 항목만 후보가 된다.
- 동일 바이트는 SHA-256으로, 가벼운 시각 변형은 pHash·dHash와 화면비 차이로 순위를 정한다.
- 결과는 최대 20건이며 공개 라이브러리 카드와 상세 페이지로 연결한다.
- 이 단계는 사물·주제·분위기만 비슷한 사진을 찾는 의미 기반 검색이 아니다. 그 기능은 임베딩 모델, 개인정보 국외 이전, 비용, 재색인 정책을 결정한 뒤 2단계로 도입한다.

## 판정 분리

중복 차단과 사진 검색은 지문 생성만 공유하고 임계값과 결과 처리는 분리한다.

- 중복 차단: 같은 사진가의 SHA-256 일치만 즉시 차단한다. 타 사진가의 exact 또는 매우 엄격한 pHash·dHash 후보는 관리자 검토로 보낸다.
- 사진 검색: 공개 이미지에 한해 더 넓은 pHash·dHash 범위를 순위화한다. 검색 결과는 차단이나 관리자 상태를 변경하지 않는다.

검색 점수는 exact 일치를 최우선으로 두고, 그 외에는 pHash 거리 18 이하, dHash 거리 10 이하, 화면비 차이 15% 이하를 모두 만족하는 후보를 낮은 거리 순으로 정렬한다. 동점은 이미지 ID로 안정적으로 정렬한다.

## 요청·보안

- API: `POST /api/images/search-by-photo`, `multipart/form-data`의 `image` 필드
- 선택 원본 최대 25MB, 서버 요청 파일 최대 3.5MB·3메가픽셀, 허용 형식은 JPEG·PNG·WebP
- IP 기준 분당 20회 분산 rate limit을 적용하고 limiter 장애 시 닫힌 상태로 실패한다.
- 선언된 Content-Length와 실제 파일 크기를 모두 검사하고 Sharp metadata로 형식·크기를 다시 확인한다.
- 검색 원본, EXIF, 파일명, SHA-256, pHash, dHash는 DB·Storage·운영 로그·응답에 남기지 않는다.
- 성공과 오류 응답은 `private, no-store`로 반환한다.
- service role은 지문 테이블을 읽는 데만 사용하며 응답 데이터는 공개 상태를 먼저 통과한 이미지로 제한한다.

## UI 흐름

1. 텍스트 검색창 옆 카메라 버튼으로 파일을 선택한다.
2. 처리 중에는 검색 상태를 알리고 중복 제출을 막는다.
3. 성공하면 사진 검색 모드임을 나타내는 배너와 결과를 표시한다.
4. 결과가 없으면 이 기능의 근접 일치 한계를 설명하고 텍스트 검색을 안내한다.
5. `사진 검색 종료`를 누르면 기존 텍스트·필터 검색 결과로 돌아간다.

브라우저 object URL은 선택한 이미지를 화면에 직접 표시하지 않으므로 만들지 않는다. 파일명도 서버에 표시하거나 보관하지 않는다.

## 데이터와 확장 기준

1단계는 공개 이미지 최대 2,000건과 그 지문만 서버에서 읽어 애플리케이션에서 순위를 계산한다. 현재 공개 카탈로그 규모에서는 단순하고 감사하기 쉬운 방식이다. 공개 지문 보유 이미지가 1,500건에 이르면 DB 내 거리 계산 RPC 또는 벡터 인덱스로 이전하는 운영 과제를 시작한다.

Vercel Function의 요청·응답 본문 한도는 4.5MB이므로 검색본과 multipart 부가 데이터를 합쳐 그보다 작게 유지한다. 원본을 임시 Storage에 올려 한도를 우회하지 않는다.

2단계 의미 기반 검색은 다음 결정이 선행되어야 한다.

- 자체 호스팅 또는 외부 임베딩 공급자
- 검색 입력과 카탈로그 이미지의 국외 이전·보유·삭제 정책
- 모델 버전별 전체 재색인 및 롤백 방법
- 정확도 평가셋, 응답시간, 월 비용 기준

## 검증

- 순수 랭킹 테스트: exact 우선, 근접 변형 순위, 임계값 밖 제외, 알고리즘 불일치·잘못된 지문 제외
- 정책 테스트: API의 공개 상태 필터, 크기 제한, rate limit, no-store, 비저장 원칙이 코드와 문서에 존재하는지 확인
- 전체 `vitest`, TypeScript, lint, Next production build를 통과한다.
