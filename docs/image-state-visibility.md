# 이미지 상태와 화면 노출 기준

이미지는 검토 상태(`status`), 생명주기(`lifecycle_status`), 공개 스위치
(`is_published`)를 함께 판단한다. 어느 한 필드만 보고 노출 여부를 결정하지 않는다.

| 상태 | 사진가 `내 업로드` | 관리자 `이미지 검토` | 일반 구매자·검색·장바구니 |
| --- | --- | --- | --- |
| 검토 대기 + active | `검토 중` | `검토 대기`에서 조회·승인·반려 | 노출 안 함 |
| 승인 + active + 공개 | `승인됨` | `승인됨`/`전체`에서 조회 | 노출·구매 가능 |
| 승인 + active + 공개 중지 | `승인됨`과 `공개 중지` 표시 | `승인됨`/`전체`에서 조회 | 노출·신규 구매 불가 |
| 반려 + active | `반려됨`에서 보관기간 동안 조회·수정·재검토·삭제 | `거절됨`에서 조회 | 노출 안 함 |
| 삭제 요청 | `삭제·비공개`에서 진행 상태 조회 | 삭제 요청 관리 화면 및 `전체`에서 조회 | 즉시 노출·신규 구매 불가 |
| archived | `삭제·비공개`에서 조회 | 이미지 검토 목록에서는 제외, 삭제 관리에서 조회 | 노출·신규 구매 불가 |
| purged | 실제 DB 기록이 남아 있는 동안 `삭제·비공개` 표시 | 이미지 검토 목록에서는 제외 | 노출·신규 구매 불가 |
| legal_hold | `삭제·비공개`에서 `권리 검토 중` 표시 | `전체` 및 권리 검토 업무에서 조회 | 노출·신규 구매 불가 |
| 실제 DB 완전삭제 | 조회 불가 | 조회 불가 | 조회 불가. 주문 당시 스냅샷만 보존 |

## 상태 전이

1. 새 업로드는 항상 `pending + active + is_published=false`로 생성한다.
2. 관리자가 승인하면 `approved + active + is_published=true`가 된다.
3. 관리자가 반려하거나 승인을 취소하면 `rejected + active + is_published=false`가 된다.
4. 사진가가 반려 이미지를 수정해 재검토를 요청하면
   `pending + active + is_published=false`로 돌아간다.
5. 삭제 요청을 생성하는 즉시 `is_published=false`로 바꾸고 장바구니에서 제거한다.
6. Arweave 자격증명이 없는 이미지는 즉시 `archived`로 전환한다. 원본과 DB의
   물리 삭제는 관리자가 별도 처리한다.
7. Arweave 자격증명이 있는 이미지는 `deletion_requested`로 전환하고 관리자가
   비용·권리·구매이력을 검토한다.
8. 반려 이미지는 관리자 설정 보관기간이 지나면 자동으로 `archived`가 되고
   사진가 목록에서도 사라진다.

## 화면 갱신

- 사진가와 관리자 목록은 브라우저 포커스 복귀 시, 30초마다, 그리고 사용자가
  `새로고침`을 누를 때 서버에서 다시 읽는다.
- 목록 API는 개인 데이터이므로 `private, no-store`로 응답한다.
- 조회 실패는 빈 목록처럼 숨기지 않고 오류와 재시도 버튼을 표시한다.
